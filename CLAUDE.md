# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

pnpm workspace (`packages/*`, `apps/*`). No linter is configured.

- `pnpm dev` — Vite dev server for the demo app (`@bloco/web`)
- `pnpm build` — `tsc && vite build` for the demo app
- `pnpm --filter ./packages/ui exec tsc --noEmit` — typecheck the UI package (includes tests)
- `pnpm test` — Vitest in every package (`packages/ui` + `apps/web` layer check); `pnpm test:coverage` — `packages/ui` only, fails below 80%

## Architecture

- `packages/ui` (`@bloco/ui`, private, consumed as source: `main` points to `src/index.ts`) — the design system. React 19, Tailwind v4, `class-variance-authority`, `react-aria-components`, Phosphor icons. `src/` is split by DS layer ([ADR 0017](docs/decisions/0017-pastas-por-camada-no-pacote-ui.md)): `foundations/` (tokens), `components/<kebab-name>/`, `patterns/<name>/`; `src/index.ts` exports only components.
- `apps/web` (`@bloco/web`) — TanStack Start (SPA mode) demo catalog and project starter ([ADR 0014](docs/decisions/0014-tanstack-start-no-app.md)); file routes in `src/routes/`. Four layers ([ADR 0015](docs/decisions/0015-camadas-do-app-web.md)): `routes` (routing + composition only, shared layout = pathless `_pages.tsx`), `domain/<name>/` (business rules), `ui` (dumb app compositions of DS components + `ui/styles/`), `global` (auth, clients). Deps: routes → domain/ui/global; domain → domain/ui/global; ui → ui + `@bloco/ui`; global → global. Cross-layer imports use `@/<layer>/…`; enforced by `apps/web/src/layers.test.ts`. Naming (ADR 0015): all files kebab-case (`app-sidebar.tsx` exports `AppSidebar`); `ui` components = generic market names (`AppSidebar`); `domain`/`global` components = `{Domain}{Kind?}{Thing}` (`DocsPropsTable`); functions/consts short verb+noun (`findDoc`), ≤3 words, don't repeat the scope. Componentization (ADR 0015): extract any JSX chunk with its own role into a named component (the `AppLayout` header is `AppHeader`, not inline JSX), and **one component per file** in every `ui`/`domain`/`global` file (incl. `data/`, `examples/`; shared example parts go in sibling files), even tiny helpers (`app-header.tsx`, `menu-toggle.tsx`). File casing and one-component-per-file are checked by `layers.test.ts`. Docs catalog ([ADR 0016](docs/decisions/0016-catalogo-como-site-de-docs.md)): one page per DS item at `/<layer>/<slug>` (`/components/button-group`), one `Doc` per file in `src/domain/docs/data/<layer>/<slug>.tsx` (`title` PascalCase, `examples` with `code`, `props`, `context` = the `.context.md`/`.pattern.md` imported `?raw`), registered in `data/docs.ts`; each example is a self-contained file (only `@bloco/ui`, icons, react and sibling part files) in `src/domain/docs/examples/<layer>/<slug>/<name>.tsx` imported as component + `?raw`; `DocsPage` renders it (header, examples with code, do/don't from `Quando usar`/`Quando não usar`, sections, props), `DocsNavigation` builds the sidebar, the "Nesta página" TOC goes in the shell's `sidebarRight`. A new component needs a page there to show up (`/create-component-docs`).
- `packages/ui/src/patterns/<name>/` — patterns layer (ADR 0011, [ADR 0012](docs/decisions/0012-estrutura-da-camada-de-patterns.md)): composition docs for agents, `<name>.pattern.md` + typed `<Name>.example.tsx` (imports only `@bloco/ui`), index in `patterns/README.md`, not exported from `index.ts`, no new styles/props. Create/update with `/create-pattern` ([.claude/skills/create-pattern/SKILL.md](.claude/skills/create-pattern/SKILL.md)).
- `packages/ui/src/foundations/index.css` — foundations entry (exported as `@bloco/ui/foundations.css`); it only imports partials from `packages/ui/src/foundations/` (`color.css`, `typography.css`, `spacing.css`, `layout.css`). Primary/neutral = slate, accent = amber.
- Foundations (ADR 0005 + 0006, [docs/architecture/theming.md](docs/architecture/theming.md)): Carbon model on top of Tailwind primitives. Components use **only semantic tokens** with Carbon names, each in its property namespace: `bg-background`, `bg-layer-01..03` (+`-hover`/`-selected`, depth by layer, not shadow), `bg-field-01`, `bg-interactive` + `text-on-color`, `bg-accent` + `text-on-accent`, `text-primary/secondary/helper/placeholder/accent`, `text-icon-*`, `border-subtle/strong/interactive`, `outline-focus`, `support-*`. Type set: `text-body-01`, `text-body-compact-01`, `text-label-01`, `text-heading-01..07`… (weight included; no `font-medium/bold`). Spacing only Carbon steps `0.5 1 2 3 4 6 8 10 12 16 20 24 40`; control heights `h-control-xs..xl`; no `rounded-*` (except `rounded-full`); only `shadow-floating` for menus/popovers. No primitive colors, hex, arbitrary colors or opacity modifiers in `*.styles.ts` — enforced by `packages/ui/src/foundations/tokens.test.ts`. Layout (ADR 0008): grid 4/8/16 cols with responsive gutter; compose with `Grid`/`Stack`/`Cluster`/`Sidebar` (parent owns `gap`, components set no outer margin); containers `max-w-prose/reading/page`, `w-sidebar`; no arbitrary breakpoints (`min-[…]`). Missing token → add it to its category partial with a one-line usage comment, valued from Tailwind primitives. Component tokens (`--bl-<comp>-<prop>`) only in `X.module.css` under `bl:<name>`, valued from semantic tokens, only when a value is single-component and can't be a utility (animation, specific behavior).

### Component conventions (`packages/ui/src/components/<kebab-name>/`)

- `X.tsx` + `X.styles.ts` + `index.tsx`. All Tailwind classes live in `.styles.ts` as a `cva` (`xStyles`, `XStyleProps`); no inline classes in TSX.
- The `BL` prefix appears **only** in the folder's `index.tsx` re-export and in `packages/ui/src/index.ts` (e.g. `Button as BLButton`). Internally everything uses the plain name.
- Components always accept `className` and pass it last into the cva call so consumers can override.
- Compose from existing DS components first (e.g. `Button`), then unstyled `react-aria-components` for anything interactive (ADR 0003, [docs/architecture/components.md](docs/architecture/components.md)), before writing from scratch. RAC components style state via `data-hovered:`/`data-pressed:`/`data-selected:`/`data-disabled:`, focus via `data-focus-visible:` + `outline-focus`, and merge `className` with `composeRenderProps`. Don't add dependencies without asking.
- Tests (ADR 0004, [docs/decisions/0004-testes-com-vitest.md](docs/decisions/0004-testes-com-vitest.md)): every component has `X.test.tsx` next to `X.tsx`, behavior only — `getByRole` + `userEvent`; callbacks, state, `disabled`, ARIA, focus, `className` passthrough. Never assert DS classes, `toHaveStyle` or snapshots. New components ship with their test.
- Extra CSS (keyframes, complex selectors) goes in `X.module.css` with a `bl:<name>` class, referenced from `.styles.ts`.
- Context (ADR 0009, [docs/decisions/0009-documento-de-contexto-por-componente.md](docs/decisions/0009-documento-de-contexto-por-componente.md)): every component has `X.context.md` next to `X.tsx` — purpose, when (not) to use, semantics/a11y, functional meaning of props, composition, decisions. Written for AI first, readable by humans; no classes/tokens. Generate or update it with `/create-component-context` ([.claude/skills/create-component-context/SKILL.md](.claude/skills/create-component-context/SKILL.md)); API or semantic changes update it in the same commit.
- Form fields (ADR 0010, [docs/decisions/0010-padrao-de-form-fields.md](docs/decisions/0010-padrao-de-form-fields.md)): every field (select, input, textarea, checkbox…) is a RAC field composing `FieldLabel`, `FieldHelperText` and `FieldFeedback` — never its own label/help/error styles. Placeholder = `text-placeholder`; disabled = `text-disabled`/`border-disabled`/`text-icon-disabled` tokens, not `opacity-*`.

Use the `/create-component` skill ([.claude/skills/create-component/SKILL.md](.claude/skills/create-component/SKILL.md)) when adding a component; it holds the full checklist. After adding one, export it from `packages/ui/src/index.ts`, write its test and its context, add its docs page (`/create-component-docs`, [.claude/skills/create-component-docs/SKILL.md](.claude/skills/create-component-docs/SKILL.md)), typecheck and run `pnpm test:coverage`.
